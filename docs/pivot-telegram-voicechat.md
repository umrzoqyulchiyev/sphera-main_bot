## 🔑 ПОЧЕМУ ОТКАЗЫВАЕМСЯ ОТ РАДИО-ФОРМАТА (Icecast)

| Причина | Радио (Icecast) | Telegram Group Voice Chat |
|---------|-----------------|---------------------------|
| **Юридически** | ❌ Нужна лицензия на вещание (закон) | ✅ Группа — музыкой делятся свободно, лицензия не нужна |
| **Музыка** | ❌ Трансляция = нарушение без лицензии | ✅ В группе делиться музыкой легально |
| **Данные** | ❌ Шаблонное радио НЕ использует данные слушателей | ✅ Собираем мнения → большинство → сразу применяем |
| **Ресурсы** | ❌ Свой сервер тянет весь трафик (дорого) | ✅ Инфраструктура Telegram (бесплатно) |
| **Уникальность** | ❌ Обычное радио, таких много | ✅ Новый формат, такого ещё нет |

**Вывод Босса:** Формат группы выигрывает и юридически, и технически, и по
бизнес-модели (данные + музыка + бесплатная инфраструктура Telegram).

## 🛠 ТЕХНОЛОГИИ: какие есть варианты и что лучше

### Управление Voice Chat в Telegram-группе — 3 варианта:

#### Вариант A — Pyrogram + pytgcalls (userbot)
- **Что:** userbot-аккаунт через MTProto управляет групповым звонком.
- **Может:** заходить в Voice Chat, стримить аудио, мьютить/размьютить участников.
- **Плюсы:** полный контроль, можно стримить готовое аудио (для AI-эфира потом).
- **Минусы / ОГРАНИЧЕНИЯ:**
  - ❗ Нужен **реальный Telegram-аккаунт** (номер телефона), не Bot API.
  - ❗ pytgcalls требует Node.js + ntgcalls бинарники, FFmpeg.
  - ❗ Userbot-аккаунт может попасть под ограничения Telegram при злоупотреблении.

#### Вариант B — Bot API (обычный бот)
- **Что:** обычный бот-администратор группы.
- **Может:** управлять правами участников группы (banChatMember, restrictChatMember).
- **ОГРАНИЧЕНИЕ:** ❗ Bot API **НЕ управляет микрофоном в Voice Chat напрямую**.
  Voice Chat (групповой звонок) недоступен через Bot API — только через MTProto.
- **Вывод:** для управления именно микрофоном Voice Chat — Bot API не хватает.

#### Вариант C — Telegram права администратора группы (ручное)
- **Что:** Voice Chat имеет встроенное управление — админ может мьютить участников.
- **ОГРАНИЧЕНИЕ:** ❗ Ручное, не программное. Для автоматизации нужен Вариант A.

### 📌 РЕКОМЕНДАЦИЯ

**Вариант A (Pyrogram + pytgcalls)** — единственный, который даёт **программное**
управление микрофоном в Voice Chat + возможность стримить аудио (понадобится для
AI-эфира). Это стандарт индустрии для таких задач (так работают музыкальные боты
типа Lemon, Yukki Music и др.).

## ⚠️ ЧЕСТНЫЕ ОГРАНИЧЕНИЯ (о которых нужно знать заранее)

1. **Userbot обязателен.** Telegram Voice Chat нельзя контролировать обычным
   ботом (Bot API). Нужен реальный аккаунт (номер телефона) для userbot.
2. **pytgcalls — это «один источник».** Userbot транслирует ОДИН аудиопоток в
   Voice Chat. Живые участники говорят через свои микрофоны (нативно Telegram).
   То есть: либо userbot стримит готовое аудио (AI-диалог/музыка), либо люди
   говорят сами — смешивать в один поток сложно.
3. **Мьют/размьют** через MTProto работает, но Telegram периодически меняет API —
   нужно следить за версией Pyrogram/pytgcalls.
4. **Масштаб Voice Chat:** Telegram Voice Chat поддерживает тысячи слушателей,
   но одновременно говорящих — ограниченное число. Для «радио» (1 говорит,
   тысячи слушают) — подходит идеально.

## 🔄 ЧТО МЕНЯЕТСЯ В ПРОЕКТЕ

| Было (Icecast-радио) | Стало (Telegram Voice Chat) |
|----------------------|------------------------------|
| Icecast + FFmpeg + свой стриминг | Telegram Voice Chat (родной) |
| Свой аудио-плеер в Mini App | Слушают прямо в Telegram |
| Лицензия на вещание нужна | Не нужна (группа) |
| Сервер тянет трафик | Telegram тянет трафик |
| `/radio/live/{lang}` proxy | Не нужен |
| pytgcalls — для AI-эфира (стрим готового аудио в Voice Chat) | Основной инструмент |

**Что остаётся без изменений:**
- Профиль, ID, уровни, поинты (transfer/request) — всё в силе.
- Сбор мнений (текст/голос) через Telegram — в силе.
- Бот + Mini App для профиля/поинтов/управления — в силе.
